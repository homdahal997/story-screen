## Part B — The exact pipeline from the reference (what "generate" runs)
Each episode is produced by the user's own multi-stage pipeline, using the same providers,
models, and settings found in the reference code:

1. **Setup (Synopsis)** — LLM proposes a title + synopsis from the premise. (Emergent LLM.)
2. **Script (Screenplay)** — LLM returns the structured manifest: `global_style`, `characters`
   (each with an ultra-detailed `detailed_visual_profile`), and `scenes` (each with
   `visual_prompt`, `camera_movement`, `dialogue` + speaker-tagged `dialogue_lines`,
   `character_focus`). A **locked random seed** is stored for consistency. (Emergent LLM.)
3. **Assets** —
   - **Character references**: one image per character from its visual profile.
   - **Scene storyboards**: generated by **reusing the character reference images** as inputs so
     faces, hair, and wardrobe stay identical across scenes. (Gemini "Nano Banana" image model,
     seed-locked, orientation-aware.)
4. **Motion** — each storyboard is animated by **Replicate Luma Ray 3.2** (image-to-video, 5s
   per shot). Clips are downloaded and archived so they're reused, never re-billed.
5. **Voice (ElevenLabs)** — the user picks/【auto-assigns】**one locked ElevenLabs voice per
   character** (`voice_assignments`); every line that character speaks is synthesized with that
   same voice (`eleven_multilingual_v2`, the reference's exact voice settings) and archived as MP3.
6. **Lip-sync (PixVerse via Replicate)** — for each dialogue line, a character-focused shot is
   lip-synced to that line's ElevenLabs MP3 using Replicate model `pixverse/lipsync`
   (`{video, audio}`). The lip-synced clip becomes that line's final shot. **This uses the same
   Replicate token already provided — no separate PixVerse key.**
7. **Assembly / Preview** — the scene shots (motion + lip-synced dialogue shots) play back to back
   as the episode preview, in the app's player.

All artifacts (images, clips, voices, lip-synced clips) are saved to the account and reused, exactly
as the reference's "salvage/normalize and never re-bill" approach intends.

## Part C — Series → Episodes structure
- A **project = a series** (title, style, ratio, episode count from Create Work; the raw idea is
  the series premise).
- **Opening a project shows the episode list** (`Episode 1 … Episode N`) with per-episode status
  and lock state.
- **Tapping an unlocked episode** runs the pipeline above for that episode.
- Episodes are empty slots until opened, so a 10/45/60-episode series is created instantly and
  costs nothing until an episode is generated.
- Per-episode stories come from the series premise + episode number + a short "story so far".

## Part D — Complete Episode 1 first (locking)
- Only **Episode 1 is unlocked**; **Episodes 2…N are locked** with a lock badge.
- When **Episode 1 is Ready** (its shots generated through lip-sync), **all remaining episodes
  unlock**.

## Part E — Episode length 1:00–1:20
- Each episode targets **60–80 seconds**, assembled from its scene shots (each Luma shot is 5s;
  dialogue scenes add a lip-synced dialogue shot). The number of scenes/shots is chosen so the
  episode lands in that range.
- Playback is back-to-back in the app. A single **downloadable stitched file** (the reference did
  this in-browser as WebM) would be produced **server-side** and is a follow-up, not part of this
  round.
